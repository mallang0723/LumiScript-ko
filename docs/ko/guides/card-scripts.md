# 캐릭터 카드에 스크립트 묶기

LumiScript 스크립트는 **캐릭터 카드 안에 함께 담아** 배포할 수 있어요. 스크립트 몇 개를 캐릭터 카드에 묶은 뒤 일반적인 Lumiverse 방식으로 카드를 내보내면, 그 카드를 가져오는 사람에게 해당 스크립트의 설치를 제안해요. 사용자는 코드를 직접 검토하고 동의한 뒤 설치할 수 있으며, 안전을 위해 처음에는 **비활성화됨** 상태로 설치돼요. 전용 상태 추적기나 주사위 굴림 도구, 장면 템포 로직처럼 캐릭터와 함께 동작해야 하는 기능을 배포할 때 가장 간편한 방법이에요.

이 기능은 `.lumiscript.zip` [스크립트 팩](#vs-script-packs)과 짝을 이뤄요. 스크립트 팩이 독립된 파일로 전달하는 형태라면, 카드 내장 스크립트는 이미 공유하고 있는 캐릭터 카드 안에 포함되어 전달돼요. 내부적으로는 동일한 스크립트 서브셋을 사용하며, 카드 항목은 팩 항목에 고유한 번들 ID가 추가된 형태예요.

이 기능은 별도의 `api.*`가 없어요 — UI 기반 기능(작성 모달 및 가져오기 동의 절차)이므로 이 문서는 API 레퍼런스가 아닌 사용 안내 가이드예요.

## 한눈에 보기

| | |
|---|---|
| **묶기 (작성)** | 스크립트 관리자 툴바 → **묶기** 버튼(상자 아이콘) → 스크립트와 대상 캐릭터 선택 → 해당 캐릭터의 `extensions.lumiscript`에 스크립트가 기록돼요. 평소처럼 카드를 내보내면 스크립트가 함께 포함돼요. |
| **직접 편집** | 캐릭터 편집기의 **LumiScript** 탭에서 카드에 묶인 스크립트를 확인(설치 상태 배지 포함)하거나, 제거하고, 내 라이브러리에서 스크립트를 추가하거나 바로 가져올 수 있어요. 최신 Lumiverse(편집기 탭 호스트 API 지원)가 필요하며, 이전 버전 호스트에서는 탭이 표시되지 않아요. |
| **가져오기** | 카드를 가져올 때 **동의 창**에 묶인 스크립트 목록이 나타나요. 가져오는 사용자가 검토 후 설치할 스크립트를 선택해요. 설치 시에는 안전을 위해 **비활성화됨** + `allowDangerous: false` 상태로 들어와요. |
| **신뢰 모델** | 카드를 가져오는 행위 자체가 신뢰의 시작이에요. 코드를 검토하기 전까지는 어떤 스크립트도 자동으로 활성화되거나, 자동 실행되거나, 권한을 스스로 승인받지 않아요. 사용자가 패널에서 코드를 검토한 뒤 활성화해야 해요. |

## 카드에 스크립트 묶기 (작성 절차)

스크립트 관리자 툴바에 **묶기** 버튼(가져오기/내보내기 옆 상자 아이콘)이 있어요. 클릭하면 모달 창이 열려요:

1. **스크립트 선택** — 보유 중인 모든 스크립트(트리거와 라이브러리 모두)의 체크리스트가 표시돼요. 묶고 싶은 스크립트를 체크하세요.
2. **대상 캐릭터 선택** — 내 캐릭터 목록 드롭다운(초상화 썸네일이 함께 표시되어 이름이 같은 캐릭터도 쉽게 구분할 수 있어요)에서 고르세요. 선택한 캐릭터의 카드에 스크립트가 기록돼요.
3. **확인** — 백엔드가 선택한 스크립트를 직렬화하여 캐릭터의 `extensions.lumiscript`에 기록해요. 그 후 Lumiverse의 일반적인 캐릭터 내보내기 기능을 통해 **해당 캐릭터를 내보내면** 스크립트가 포함된 카드가 완성돼요.

(각 스크립트가 이 캐릭터에서만 실행될지, 아니면 모든 채팅에서 실행될지는 여기서 결정하지 **않아요**. 이는 카드를 가져오는 사람이 동의 창에서 결정할 몫이에요. 가져오기 절의 [범위 지정](#scoping--run-only-for-this-character)을 참고하세요.)

기록 작업은 백엔드에서 안전하게 처리돼요. 모달은 선택한 스크립트 ID와 대상 캐릭터 정보만 전송하며, 백엔드가 저장소에서 실제 스크립트 본문을 불러와 번들을 구성해요. 카드 데이터 중 오직 `lumiscript` 키만 기록하므로(호스트가 얕은 병합을 수행하여 다른 확장의 데이터는 건드리지 않아요), 다시 내보낼 때도 기존 번들 ID를 재사용하여 중복 생성이 아닌 업데이트로 처리돼요.

### 카드에 포함되는 것과 제외되는 것

묶인 스크립트에는 스크립트 팩과 동일하게 **공유 가능한 서브셋**만 포함되며, 로컬 환경 정보는 제외돼요:

| 카드에 포함되는 항목 | 제거되는 항목 (가져올 때 안전한 기본값으로 재생성) |
|---|---|
| `name`, `code`, `type` (trigger / library) | 설치된 스크립트의 `id` (가져올 때 새 UUID 발급) |
| **`triggers`** — 이벤트 훅 (수신 대기할 Lumiverse 이벤트 목록) | `enabled` — 가져오면 **비활성화됨** 상태로 설치 |
| `folder`, `metadata` (`description` / `author` / `version` / `tags`) | `allowDangerous` — 가져오면 **`false`**로 설정 |
| | 타임스탬프 (생성/수정 시각) |

특히 중요한 점은 **`triggers`**예요: 묶인 트리거 스크립트의 이벤트 훅 전체가 카드에 보존되어 가져올 때 그대로 적용돼요. 따라서 가져오는 사람이 어떤 이벤트에 연결해야 할지 주석을 찾아 읽을 필요가 없어요. (스크립트는 비활성화 상태로 설치되므로 활성화하기 전까지 훅은 *설정만 되어 있고 대기* 상태예요. 활성화하는 즉시 작성자가 지정한 이벤트들을 수신하기 시작해요.)

**바인딩은 특별한 경우예요.** 바인딩은 카드에 기록되기는 하지만(공유 가능 서브셋에 포함됨), **설치 시점에는 버려져요**. 바인딩에 기록된 캐릭터 UUID는 카드를 가져온 다른 사용자의 컴퓨터에서는 유효하지 않기 때문이에요. 대신 동의 창의 범위 토글을 통해 새 바인딩을 생성해요. 즉 파일 안에는 들어가지만 설치된 스크립트에는 직접 적용되지 않아요. 자세한 내용은 [범위 지정](#scoping--run-only-for-this-character)을 참고하세요.

### 사전 경고 안내

모달은 묶기 전에 다음과 같은 상황에서 경고를 표시해요:

- 스크립트가 **64개**를 초과하여 선택된 경우 (가져오기 쪽에서 최대 64개까지만 허용해요).
- 이름/폴더/메타데이터 필드가 가져오기 길이 제한을 초과한 경우 (가져올 때 잘릴 수 있어요).
- 선택한 스크립트에 캐릭터/채팅 바인딩이 걸려 있는 경우 (가져가는 사람에게는 전달되지 않으며 동의 창에서 다시 지정해야 한다는 안내예요. [범위 지정](#scoping--run-only-for-this-character) 참고).

## 캐릭터 편집기 LumiScript 탭

Lumiverse의 캐릭터 편집기에서 캐릭터를 열면 **LumiScript** 탭이 있어요. 툴바 모달보다 훨씬 풍부한 기능을 제공해요. 편집기에서 **임시 저장(draft)** 중인 `extensions.lumiscript`를 실시간으로 읽어 해당 카드에 묶인 스크립트 목록을 보여 줘요. 각 스크립트의 타입(트리거/라이브러리), 버전, 이벤트 훅, 코드 크기, 폴더, 바인딩 안내 문구와 함께 **설치 상태 배지**를 확인할 수 있어요:

- **라이브러리에 있음** — 이미 내 라이브러리에 있는 스크립트예요 (`(bundleCardId, bundleId)` 또는 동일한 코드로 판별하므로, 내 라이브러리에서 방금 카드에 묶은 스크립트도 중복 설치를 유도하지 않고 보유 중으로 표시돼요).
- **라이브러리에 없음** — 카드에는 들어 있지만 아직 내 라이브러리에 설치하지 않았어요.
- **업데이트 있음** — 카드에 포함된 스크립트가 내 라이브러리에 설치된 것보다 최신 버전이에요.
- **라이브러리가 최신** — 내 라이브러리에 설치된 사본이 카드의 것보다 앞서 있어요.

이 탭에서는 다음 작업을 할 수 있어요:

- **카드에서 스크립트 제거** — 휴지통 아이콘(확인 절차 포함)을 눌러 제거해요. **카드**에서만 수정되며, 내 라이브러리에 이미 설치된 스크립트는 그대로 남아요. 변경 사항은 **자동 저장**되어 캐릭터 편집기가 즉시 반영하고, 마지막 남은 스크립트를 제거하면 `lumiscript` 키 전체가 삭제되어 깨끗한 카드가 돼요.
- **내 라이브러리에서 스크립트 추가** — **추가** 버튼을 누르면 내 스크립트 목록(이미 카드에 있는 것은 제외되고, 각 항목에 트리거/라이브러리 배지가 붙어요)이 인라인으로 열려요. 원하는 스크립트를 선택하고 **카드에 추가**를 누르면 편집 중인 캐릭터에 묶여요. 툴바 모달과 마찬가지로 백엔드에서 안전하게 실제 저장된 스크립트를 바탕으로 항목을 구성하지만, 드롭다운에서 고른 캐릭터가 아니라 열려 있는 캐릭터를 대상으로 하며, 카드의 기존 번들 ID를 재사용해요(번들 ID가 없던 카드에는 새로 발급해요).
- **라이브러리로 가져오기** — 카드에 아직 설치하지 않은 스크립트가 있을 때 **라이브러리로 가져오기** 버튼을 누르면 편집기를 벗어나지 않고도 동일한 [동의 창](#importing--the-consent-flow)(범위 토글, 권한 경고, 스크립트별 선택)이 열려 그 자리에서 바로 설치할 수 있어요. 안전을 위해 **비활성화됨** 상태로 설치되며, 탭의 화면이 아닌 실제 저장된 카드의 데이터를 읽어 백엔드에서 안전하게 처리해요.

툴바의 **묶기** 버튼과 편집기 탭은 용도가 달라요: *다른 캐릭터*에 스크립트를 묶고 싶을 때는 툴바 모달을 쓰고, *현재 편집 중인 카드*를 관리할 때는 편집기 탭을 쓰세요.

## 가져오기 — 동의 절차

`extensions.lumiscript`가 포함된 카드를 가져오면 호스트가 `CHARACTER_CREATED` 이벤트를 발생시키고, LumiScript가 번들을 읽어 조치할 내용이 있으면 **동의 창**을 띄워요. 스크립트마다 다음 정보가 표시돼요:

- **이름** 및 **동작 배지** — `설치`, `업데이트 v1.0.0 → v1.1.0`, `최신 버전`, `이전 버전 — 건너뜀`, `변경 없음`.
- **설명 / 작성자 / 버전** (묶인 메타데이터 기준).
- **이벤트 훅** — 활성화되었을 때 스크립트가 수신할 이벤트 목록.
- **권한 경고** — 아직 승인하지 않은 Spindle 권한이 필요한 스크립트인 경우 경고가 표시돼요(설치를 막는 것은 **아니며**, 권한을 허용하기 전까지 일부 기능이 제한될 수 있다는 안내예요).
- **"‹캐릭터›에서만 실행"** 범위 토글.
- 덮어쓰기 경고 — 업데이트 시 **활성화됨** 상태인 스크립트 코드나 **직접 수정한 코드**를 덮어쓰게 될 때 표시돼요.

원하는 스크립트를 체크하고 확인하세요. 모든 스크립트는 **비활성화됨** 및 `allowDangerous: false` 상태로 설치돼요. LumiScript 패널에서 코드를 검토한 뒤 활성화해 주세요.

<a id="scoping--run-only-for-this-character"></a>

### 범위 지정 — "이 캐릭터에서만 실행"

바인딩(스크립트가 "캐릭터 X / 채팅 Y에서만 실행되도록" 제한하는 설정)은 **캐릭터의 고유 UUID**와 일치해야 동작해요. 하지만 호스트는 카드를 가져올 때마다 캐릭터 UUID를 새로 발급하므로, 작성자가 설정한 원래 바인딩은 **가져온 사람의 환경에서는 동작하지 않아요**. 그래서 동의 창에서는 각 트리거 스크립트마다 **"‹캐릭터›에서만 실행"** 토글을 제공해요:

- **켜짐** → 설치된 스크립트가 *이번에 가져온 캐릭터*에 바인딩돼요(해당 캐릭터가 활성 상태일 때만 실행).
- **꺼짐** → 스크립트가 전역으로 실행돼요(모든 채팅에서 실행).

작성자가 캐릭터 바인딩을 걸어 둔 트리거 스크립트는 범위를 지정하라는 의도로 보아 기본값이 **켜짐**으로 설정되고, 그 외에는 꺼짐으로 설정돼요. 라이브러리는 `require()` 호출을 바인딩으로 제한하지 않으므로 토글이 제공되지 않아요. 범위 지정은 **설치 시점에만** 결정하는 사항이에요. 나중에 *업데이트*를 다시 가져올 때는 기존에 수동으로 설정해 둔 바인딩을 덮어쓰거나 바꾸지 않아요. 범위를 변경하려면 스크립트의 바인딩 설정 패널을 이용하세요.

### 다시 가져올 때의 업데이트 처리

카드의 스크립트는 `(bundleCardId, bundleId)` 쌍을 기준으로 이미 가지고 있는 스크립트와 비교돼요(아래 [식별자](#identity--how-re-imports-match) 참고). 일치하는 항목이 발견되면:

- 양쪽 모두 **엄격한 semver** 형식의 `metadata.version`을 가지고 있는 경우 → 가져오는 버전이 **더 높으면** 업데이트로 제안되고, 같거나 낮으면 건너뛰어요(다운그레이드는 지원하지 않아요).
- 비교 가능한 버전 정보가 없는 경우 → **코드 해시**로 대체 판별해요: 코드가 완전히 같으면 건너뛰고(변경 없음), 다르면 업데이트로 제안해요.

업데이트 시에는 사용자가 설정해 둔 `enabled`, `allowDangerous` 상태와 직접 수정한 이름/바인딩은 유지되며, 코드와 트리거, 메타데이터만 갱신돼요.

### 채팅을 열었을 때 알림 배너

카드를 가져올 당시 패널을 열어 두지 않았거나, 설치를 미뤘거나, LumiScript를 설치하기 전에 카드를 먼저 가져왔을 수도 있어요. 그래서 아직 라이브러리에 설치하지 않은 스크립트가 묶인 캐릭터로 **채팅을 열면**, 관리 탭에 비차단형 **배너**가 나타나요: *"이 캐릭터에는 라이브러리에 없는 스크립트 N개가 묶여 있어요 — 검토 · 닫기."* **검토**를 누르면 동일한 동의 창이 열리고, **닫기**를 누르면 **이번 세션 동안에는 다시 표시되지 않아요**. 나중에 스크립트가 필요할 수 있으므로 재시작 후에는 다시 나타나며, [편집기 탭](#the-character-editor-lumiscript-tab)의 *라이브러리로 가져오기*를 통해서도 언제든 설치할 수 있어요. 닫기 상태는 메모리에만 유지돼요. 쌓이거나 지워야 할 닫기 기록 파일이 없고, 묶인 스크립트를 삭제한다고 해서 더 이상 그 배너가 숨겨지지도 않아요.

### 캐릭터를 삭제할 때

스크립트를 설치했던 캐릭터를 삭제하면, 해당 캐릭터가 설치했던 스크립트도 함께 정리할지 **제안**하는 창이 떠요. 기본값은 **유지**이며 자동으로 삭제되지 않아요. 묶인 스크립트라도 범용적인 도구일 수 있고 한 번 가져온 이상 사용자의 데이터이므로, 삭제 여부는 사용자가 직접 선택하도록 되어 있어요.

## 식별자 — 다시 가져올 때 일치 여부를 판별하는 방법

카드 단위의 중복 제거 키는 두 개의 ID로 구성돼요:

- **`bundleCardId`** — 작성자 UI에서 생성하여 카드에 심어 두는 ID예요. 호스트의 캐릭터 UUID와는 **달라요** (캐릭터 UUID는 카드를 가져올 때마다 새로 생성되므로 식별 기준으로 쓸 수 없어요). 같은 캐릭터를 다시 내보내면 기존 `bundleCardId`가 재사용되므로 다시 가져올 때 제자리에서 업데이트될 수 있어요.
- **`bundleId`** — 스크립트별 고유 ID로, 다시 묶어도 유지돼요. 직접 작성한 스크립트는 자체 ID를 기준으로 유지되고, 카드에서 가져온 스크립트를 다시 공유할 때도 원래 카드의 `bundleId`가 유지되어 계보가 이어져요.

이 키는 **카드별로 구분**돼요. 즉 서로 다른 두 카드에 같은 `bundleId`가 들어 있더라도 완전히 별개의 스크립트로 설치돼요. 호스트 캐릭터 UUID는 출처 기록용으로만 사용되며 고유 식별자로는 쓰이지 않아요.

## 보안 모델

- **카드를 가져오는 행위 자체가 신뢰의 시작이에요.** 별도의 서명이나 검증 단계는 아직 지원하지 않아요.
- **코드는 절대 자동 실행되지 않아요.** 설치 시 항상 비활성화됨 + `allowDangerous: false` 상태로 들어와요. 사용자가 코드를 검토하기 전까지 자동으로 켜지거나, 권한을 승인하거나, 실행되는 일은 없어요.
- **권한 경고는 안내일 뿐이에요.** 아직 허용하지 않은 권한이 필요한 스크립트라도 설치 자체가 차단되지는 않으며, 권한이 부여될 때까지 일부 기능만 안전하게 제한돼요.
- **카드는 신뢰할 수 없는 JSON 데이터로 취급해요.** 가져오기 로직은 스크립트 수량이나 필드 길이를 엄격히 제한하고 방어적으로 검증하므로 잘못되거나 악의적인 카드로 인해 프로그램이 비정상 종료되지 않아요.

## 스크립트 팩과의 비교

| | 캐릭터 카드 스크립트 | `.lumiscript.zip` 팩 |
|---|---|---|
| 전달 형태 | 공유하는 캐릭터 카드 내부에 포함 | 독립된 단일 파일 |
| 적합한 상황 | 특정 캐릭터 전용 기능일 때 (전용 상태창, 주사위 등) | 캐릭터와 무관한 범용 기능이거나, 캐릭터 없이 스크립트만 공유할 때 |
| 가져오기 UX | 카드 가져올 때 스크립트별 동의 창 + 채팅 오픈 알림 배너 | `.zip` 파일을 열 때 확인 대화상자 |
| 업데이트 | `(bundleCardId, bundleId)` 기준 최신 버전 업데이트 제안 | 다시 가져오면 새 사본으로 추가 생성 |
| 이벤트 훅 | 함께 보존되어 자동 적용 | 함께 보존되어 자동 적용 |

두 방식 모두 비활성화 상태로 설치되며 동일한 스크립트 공유 서브셋을 지원해요. 캐릭터와 함께 전달되어야 하는 스크립트라면 카드를 사용하고, 그 외에는 팩을 사용하는 것을 권장해요.

## 버전 참고 사항

캐릭터 카드 내장 스크립트 기능은 **v1.4.0 릴리스에서 새로 추가**되었어요. 작성(묶기 모달)과 가져오기(동의 창, 채팅 알림 배너, 카드 삭제 제안) 기능은 LumiScript 자체에 내장되어 있어 호스트의 `CHARACTER_CREATED` / `CHARACTER_DELETED` 이벤트와 기존 `spindle.characters.*` API만 있으면 동작해요. 반면 **캐릭터 편집기의 LumiScript 탭**(v1.4.0)은 호스트의 편집기 탭 배치 API(`ctx.ui.registerCharacterEditorTab` + `ctx.ui.characterEditor`)를 지원하는 최신 Lumiverse에서만 표시되며, 이전 버전 호스트에서는 탭만 나타나지 않고 나머지 기능은 정상 작동해요. 스크립트 팩 형식은 훨씬 이전 버전부터 동일한 서브셋을 지원해 왔어요.
