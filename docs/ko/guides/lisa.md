# Lisa와 함께 작업하기

Lisa는 LumiScript 스크립트 작성 질문에 답해 주는 앱 내 어시스턴트예요. 어떤 API 프리미티브를 써야 하는지 묻거나, 작성한 스크립트를 붙여 넣고 왜 실행되지 않는지 이유를 묻거나, 편집기를 벗어나지 않고 새 스크립트 초안을 작성해 달라고 요청할 수 있어요.

Lisa는 LumiScript 패널 안에 상주하며 LumiScript의 `api.*` 표면과 호스트 Spindle 플랫폼에 대한 질문에 답변해요. Lisa는 Q&A 및 코드 초안 작성을 돕는 도우미이며 자율 에이전트가 아니에요. 즉, 내 스크립트를 직접 실행하거나 활성 채팅, 캐릭터, 변수를 들여다볼 수 없어요. 사용자가 직접 묻는 질문 내용과 대화에 첨부한 스크립트(아래 [내 스크립트 첨부하기](#attaching-your-scripts) 참고), 그리고 사용자에 대해 보관하는 소수의 지속 메모(아래 [메모](#memory) 참고)만 알고 있어요.

## Lisa와 대화 시작하기

편집기 상단 바의 **Lisa** 버튼(실행(Run), 다시 불러오기(Reload) 옆의 말풍선 아이콘)을 클릭하거나, **스크립트 관리자 툴바**의 말풍선 버튼(가져오기/내보내기/묶기 버튼 옆)을 누르세요. 어느 쪽이든 대화창이 오버레이 형태로 열려요.

새 대화를 열면 시작하기 좋은 몇 가지 예시 질문이 표시돼요. 입력창에서 **Enter**를 누르면 메시지가 전송되고, **Shift+Enter**로 줄바꿈을 입력할 수 있어요. Lisa가 답변하는 동안 전송 버튼은 턴을 중단할 수 있는 **중지(Stop)** 버튼으로 바뀌어요. 첫 번째 토큰이 출력되기 전에 "Lisa가 생각하는 중…"이라는 표시가 나타나고, 이후 답변이 실시간 스트리밍으로 흘러나와요.

## Lisa가 알고 있는 지식과 신뢰할 수 있는 범위

Lisa의 지식은 앱 내 **레퍼런스** 탭을 구성하는 코퍼스와 동일한 데이터에서 나와요: 모든 `api.*` 메서드, 시그니처, 필요 권한, 사용 예제는 물론, 레퍼런스가 설명문으로 렌더링하는 네임스페이스별 개념 설명, 트리거 및 권한 모델 안내, 흔히 잘못 추측하기 쉬운 패턴(예: 존재하지 않는 `api.on(...)`을 찾으려는 시도 등)을 바로잡아 주는 리디렉션 가이드까지 포함되어 있어요.

한 줄 요약 정보만으로 부족할 때 Lisa는 답변 도중 해당 메서드를 전체 검색해서 살펴봐요. 대화 기록 중간에 간단한 조회 단계가 스쳐 지나가는 것을 볼 수 있는데, 이는 시그니처를 짐작으로 지어내지 않고 레퍼런스를 직접 확인하는 과정이에요.

**최종적인 진실의 원천은 Lisa가 아니라 레퍼런스 탭이에요.** Lisa는 훌륭한 어시스턴트이지만 특정 시점의 스냅샷을 기반으로 동작하는 언어 모델이므로 시그니처나 enum 값을 잘못 말할 수 있어요. 중요한 코드라면 반드시 레퍼런스 탭에서 교차 검증하거나, Lisa에게 레퍼런스를 다시 확인해 달라고 요청하세요. 만약 *레퍼런스 자체*가 틀렸거나 불명확하다면 그것은 코퍼스 버그이므로 제보해 주시면 원천적으로 수정할 수 있어요.

설계상 Lisa가 할 수 없는 일: 스크립트 직접 실행 및 테스트, 활성 채팅이나 캐릭터 데이터 읽기, 변수 수정. Lisa는 코드에 대해 추론할 뿐 코드를 직접 실행하지 않아요.

## 내 스크립트 첨부하기

내가 작성한 코드에 대해 질문하려면 입력창에 **`@`**를 입력하고 메뉴에서 스크립트를 선택하세요. 입력창 위에 칩 형태로 첨부되어 해당 턴의 컨텍스트로 함께 전달돼요. 메뉴에는 보유 중인 모든 스크립트가 표시되며 타이핑할수록 목록이 좁혀져요. 필요한 만큼 여러 개를 첨부할 수 있어요.

첨부 파일은 **대화별로 영구 유지**돼요: 나중에 해당 대화를 다시 열어도 첨부 상태가 그대로 남아 있어요. 각 스크립트의 코드는 최대 약 24 KB까지 포함돼요. 턴 사이에 첨부된 스크립트를 수정하면 Lisa에게 변경 사실이 전달되므로, 처음 보았던 옛날 버전이 아니라 현재의 수정본을 바탕으로 추론해요.

Lisa의 답변에 나온 코드를 스크립트에 다시 반영하는 것은 별개의 동작이에요. 답변 안의 모든 코드 블록에는 마우스오버 시 **적용(Apply)** 버튼이 나타나요:

- 첨부된 스크립트가 없을 때는 해당 블록으로 **새 스크립트**를 만들어요.
- 스크립트가 첨부되어 있을 때는 **새 스크립트 만들기** 또는 **«해당 스크립트» 업데이트**를 선택할 수 있어요. *업데이트*는 기존 내용을 대체하므로 확인 절차를 거친 뒤 제자리에서 코드를 덮어써요.

어느 쪽이든 대화 기록에 "이 대화로 «스크립트»를 만들었어요 / 업데이트했어요"라는 마커가 기록되므로 어떤 내용이 어디에 적용되었는지 추적할 수 있어요.

## 파일 첨부하기

때로는 Lisa에게 보여 주고 싶은 자료가 스크립트가 아니라 설계 메모나 사양서, 참고 자료 조각일 수 있어요. 입력창 옆의 **클립 아이콘**을 누르면 파일 선택기가 열려요. 여기에는 내 LumiScript 저장소의 전용 **"userfiles"** 폴더에 있는 텍스트 파일들이 나열되며, 클릭하면 스크립트와 마찬가지로 칩 형태로 첨부돼요.

파일을 넣기 위해 스크립트를 짤 필요는 없어요. 파일 선택기 안에 **파일 추가** 양식이 있어서(예: `notes.md`라는 이름을 짓고 텍스트를 붙여 넣기) 바로 추가할 수 있어요. 선택기에서 파일을 삭제할 수도 있으므로 시간이 지나면서 나만의 작은 참고 자료 라이브러리를 구축할 수 있어요. 허용되는 포맷은 텍스트 포맷(`.md`, `.txt`, `.json`, `.csv` 등)이며 파일당 최대 256 KB까지 지원해요.

파일 첨부는 스크립트 첨부와 동일하게 동작해요: **대화별로 영구 유지**되며(대화를 다시 열면 복원됨), 턴마다 최신 상태로 다시 읽고, 턴 사이에 변경되면 수정 사실이 반영돼요. Lisa는 파일의 내용을 **지시문이 아닌 참고 자료**로 취급해요. 따라서 문서 안에 우연히 "이전 지시를 모두 무시하라"는 문장이 들어 있더라도 이를 명령으로 따르지 않고 단순한 데이터로 읽어요.

범위에 대해 알아둘 두 가지: 파일 선택기에는 오직 이 전용 폴더만 노출돼요(내 스크립트나 대화 기록, 기타 LumiScript 데이터는 첨부 대상 파일로 노출되지 않아요). 그리고 현재는 **로컬 파일만** 지원해요. URL에서 파일을 바로 가져오는 기능은 향후 릴리스에 계획되어 있어요.

## 메모 (Memory)

Lisa는 사용자에 대한 소수의 **지속 메모**(직접 밝힌 선호, 반복되는 프로젝트 사실, 바로잡아 준 내용 등)를 보관하며, 대화가 바뀌어도 이를 기억해요. 이는 스크립트 첨부와는 달라요: 첨부는 한 대화 안에서의 *실시간* 코드이고, 메모는 모든 대화로 이어지는 *지속적인* 맥락이에요. (스크립트가 직접 관리하는 채팅 메모리인 [메모리 코텍스](memories.md)와는 무관해요 — 이름만 비슷할 뿐 완전히 다른 기능이에요.)

대화창 상단의 **수첩 아이콘**("메모 — Lisa가 나에 대해 기억하는 내용")을 눌러 메모 패널을 열 수 있어요. Lisa가 저장한 모든 내용이 작성자(**Lisa** 또는 **나**) 태그와 함께 나열되며, 모든 메모를 직접 추가하거나 수정, 삭제할 수 있어요. Lisa가 무엇을 기억할지는 항상 사용자가 제어할 수 있어요. **정리(Consolidate)** 버튼(메모가 6개 이상 쌓여야 실행돼요)을 누르면 모델에게 중복을 합치고 표현을 다듬어 달라고 요청할 수 있어요. 정리 과정이 어떤 이유로든 실패하더라도 기존 메모는 안전하게 그대로 보존돼요.

메모가 레퍼런스보다 우선할 수는 없어요. 메모 내용이 API 표면과 충돌하면 항상 API가 우선해요. 메모는 사용자의 취향과 작업 환경을 위한 것이지 API 세부 규격을 재정의하기 위한 것이 아니에요.

## Lisa 모델 선택하기

Lisa는 메인 채팅 모델과 별개로 내 Lumiverse LLM 연결 중 하나를 사용해 실행돼요. 롤플레잉에는 평범했던 모델이 코딩에는 뛰어난 두뇌를 발휘할 때 매우 유용해요.

- **세션별 변경:** 대화창 상단의 **연결(Connection)** 드롭다운 — 대화 중간이라도 언제든 바꿀 수 있어요.
- **기본값 지정:** 설정 → 어시스턴트 → **연결**. 여기서 선택하면 모든 새 대화가 해당 연결로 시작돼요. *Lumiverse 기본값*으로 두면 앱 전역의 기본 연결을 따라가요. 세션별 선택기는 항상 이 기본 설정보다 우선해요.

## 대화 관리 및 생성 튜닝

과거 대화 목록은 왼쪽 사이드바에 표시돼요. **새 대화**를 누르면 새 스레드가 시작되며, 각 대화 행에 마우스를 올리면 **이름 변경**, **내보내기**(대화를 Markdown으로 다운로드), **삭제** 버튼이 나타나요. 모든 대화를 한 번에 비우려면 설정 → 어시스턴트의 **모든 대화 지우기**를 사용하세요.

어시스턴트 설정 섹션에는 Lisa의 답변 방식을 조절할 수 있는 몇 가지 옵션이 있어요:

- **도구 반복 횟수** — 한 턴에 연쇄적으로 수행할 수 있는 최대 API 조회 횟수예요 (2~20, 기본값 8). 모델이 어려운 질문에서 헛돌면 낮추고, 복잡한 질문에서 한도에 걸리면 올리세요.
- **온도 / Top-P / 최대 토큰** — 비워 두면 연결 자체의 프리셋을 사용하고, 값을 입력하면 재정의해요.
- **병렬 도구 호출** — 기본적으로 켜져 있어요. 병렬 도구 사용을 잘 처리하지 못하는 프로바이더에서만 끄세요.

## 좋은 답변을 얻기 위한 팁

- **목표를 구체적으로 설명하세요.** "타이머가 어떻게 동작하나요?"보다는 "키를 누를 때마다 실행되는 핸들러에 디바운스를 걸고 싶은데 어떤 프리미티브를 써야 하나요?"가 훨씬 좋은 답변을 끌어내요.
- **질문하려는 스크립트를 첨부하세요.** 코드를 말로 풀어서 설명하는 것보다 실제 코드를 보여 주었을 때 훨씬 정확하게 추론해요.
- **표면 세부 사항을 확인하세요.** 특히 배포할 코드를 작성 중이라면 시그니처나 enum 값 등은 레퍼런스 탭을 가볍게 훑어 확인하는 습관을 들이세요.
- **잘못된 점을 지적하고 기억하게 하세요.** 내 프로젝트의 규칙이나 코딩 관례를 잘못 짚었다면 알려 주세요. Lisa가 그 교정 내용을 메모에 저장하여 다음 대화부터 반영할 수 있어요.

항상 정확하고 최신 상태를 유지하는 공식 API 정보는 앱 내 **레퍼런스** 탭이에요. 이 가이드는 *Lisa와 함께 협업하는 방법*에 대한 안내이며 레퍼런스 자체를 대체하지 않아요.
