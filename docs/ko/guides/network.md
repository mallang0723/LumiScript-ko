# 네트워크 외부 전송 및 로컬 호스트

기본적으로 LumiScript 스크립트는 **사설 네트워크 주소(localhost, LAN, 링크 로컬, 클라우드 메타데이터 엔드포인트 등)에 접근할 수 없어요**. 이 페이지에서는 그 이유와, 로컬 모델 서버나 홈랩 장비 등 필요한 특정 로컬 호스트를 허용 목록에 추가하는 방법을 설명해요.

> **v2.0 변경 사항.** LumiScript 2.0부터 사설 호스트로의 외부 전송이 기본적으로 차단돼요. 1.x에서 업그레이드하셨나요? 스크립트가 로컬 모델 서버(Ollama, ComfyUI, LM Studio)나 LAN 장비와 통신하고 있었다면, 해당 호스트를 허용 목록에 등록하기 전까지 요청이 차단돼요. 바로 아래의 [해결 방법](#the-fix-allow-specific-private-hosts)을 참고하세요.

## 기본 동작: SSRF 안전 외부 전송

스크립트가 `api.utils.http.*` 또는 순수 `fetch`(`allowDangerous` 활성화 시)를 통해 보내는 모든 외부 HTTP 요청은 호스트의 **SSRF 안전 프록시**를 거쳐요. 이 프록시는 DNS를 해석하고 고정한 뒤 대상이 다음과 같은 사설 주소로 해석되면 요청을 차단해요:

- 루프백 주소 (`127.0.0.1`, `::1`, `localhost`)
- 사설 LAN 대역 (`10.*`, `172.16–31.*`, `192.168.*`)
- 링크 로컬 (`169.254.*`, 클라우드 메타데이터 엔드포인트인 `169.254.169.254` 포함)

이는 내가 작성한 스크립트나 공유받은 캐릭터 카드에 포함된 스크립트가 악용되어 내부 네트워크를 탐색하거나 클라우드 인스턴스의 자격 증명을 가로채지 못하도록 보호하기 위한 의도적인 보안 강화 조치예요. 일반 공용 인터넷 호스트는 차단되지 않고 정상적으로 통과해요.

## 문제 상황: 로컬 모델 서버가 차단됨

스크립트가 로컬 엔드포인트(예: `localhost:11434`의 Ollama, `localhost:8188`의 ComfyUI, LM Studio, 로컬 NAS 등)를 가리키는 순간 기본 보안 규칙에 의해 요청이 거부돼요. SSRF 보호 기능이 정상 작동하는 것이지만, 정상적인 로컬 호출과 악의적인 호출을 스스로 구분할 수는 없기 때문이에요.

## 해결 방법: 특정 사설 호스트 허용하기

**설정 → 네트워크 → 허용된 사설 호스트**로 이동하세요. 스크립트가 차단을 우회해 직접 접근할 수 있도록 허용할 정확한 호스트(필요시 포트 포함)를 추가하세요:

```
localhost:11434
127.0.0.1:8188
192.168.1.50
[::1]:3000
```

이제 스크립트가 여기에 지정된 사설 주소에 한해서만 정상적으로 접근할 수 있어요.

### 규칙과 원리

- **고정 주소만 허용돼요.** 각 항목은 **IP 리터럴**이나 **`localhost`**여야 하며, 필요하면 포트를 붙일 수 있어요. 일반 도메인 호스트명(`my-nas.local`, `ollama.internal` 등)은 거부돼요. 호스트명이 접속 시점에 고정 없이 해석되면 DNS 리바인딩 취약점이 다시 발생하기 때문이에요.
- **문자열 그대로 매칭 — 리바인딩 우회 불가.** 허용 목록은 요청 URL의 호스트 부분과 *문자열 그대로(literally)* 매칭돼요. 허용 목록의 IP로 *해석될 뿐인* 공용 도메인 이름은 일치하지 않는 것으로 판정되어 차단 경로로 가요. 따라서 `127.0.0.1`을 허용하더라도 `evil.com → 127.0.0.1` 같은 DNS 트릭으로 우회할 수 없어요.
- **포트 범위 지정.** 포트가 포함된 항목(`localhost:11434`)은 해당 포트만 일치해요. 포트가 없는 항목(`192.168.1.50`)은 해당 호스트의 모든 포트를 허용해요.
- **http/https만 허용.** 허용된 호스트라도 오직 http/https 프로토콜로만 접근할 수 있어요. `file://127.0.0.1/…` 같은 URL은 거부되므로 임의의 로컬 파일 읽기로 악용될 수 없어요.
- **사용자 소유 설정.** 이 목록은 내 설정에 저장되며 **스크립트가 임의로 수정할 수 없어요**. 오직 사용자 본인만 추가/삭제할 수 있어요.

이 목록은 스크립트별 **`allowDangerous`** 토글과 짝을 이뤄요: `allowDangerous`는 스크립트에게 HTTP 기능 자체를 부여하고, 허용 목록은 그 기능이 접근할 수 있는 *사설 호스트*를 결정해요. 로컬 서버와 통신하려면 두 가지가 모두 설정되어 있어야 해요.

## 구현 예제: 로컬 Ollama 호출하기

1. 스크립트 설정에서 **`allowDangerous`**를 켜요 (외부 HTTP 전송 허용).
2. **설정 → 네트워크 → 허용된 사설 호스트**에 `localhost:11434`를 추가해요.
3. 스크립트에서 호출:

```js
const res = await api.utils.http.post(
  'http://localhost:11434/api/generate',
  JSON.stringify({ model: 'llama3', prompt: 'Say hello.', stream: false }),
  { headers: { 'content-type': 'application/json' } },
);
const { response } = JSON.parse(res.body);
console.log(response);
```

2번 단계가 없으면 요청이 SSRF 보호 기능에 의해 차단되지만, 허용 목록에 등록하면 로컬 서버로 곧바로 전송돼요. (`api.utils.http.post`의 본문은 **문자열**이어야 하므로 객체는 `JSON.stringify`로 변환해 전달하세요. 반환값은 `{ status, statusText, headers, body }`이며 `body`는 문자열이므로 직접 파싱해야 해요.)
